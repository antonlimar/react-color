title: Customizing Styles
---

React Color now exposes styling hooks in this order:

1. Import published CSS entrypoints (`es/styles/*` or `lib/styles/*`).
2. Use `theme="light" | "dark" | "auto"` to switch built-in token sets.
3. Use `className` and `classNames` to attach your own classes to supported slots.
4. Override CSS custom properties for token-level tweaks.
5. Keep `styles` only for legacy inline compatibility when migrating existing code.

### Import CSS

Use the aggregate stylesheet when you want the whole library styling surface:

```
import 'react-color/es/styles/index.css'
```

Or import only the files you need:

```
import 'react-color/es/styles/pickers/sketch.css'
import 'react-color/es/styles/common/editable-input.css'
```

### Use theme and classNames

All public pickers keep `className` on the root and additionally support `theme` and slot-level `classNames`.

```
import React from 'react'
import { SketchPicker } from 'react-color'

export default function Component() {
  return (
    <SketchPicker
      theme="dark"
      className="profile-color-picker"
      classNames={{
        root: 'profile-color-picker__root',
        body: 'profile-color-picker__body',
        controls: 'profile-color-picker__controls',
        swatch: 'profile-color-picker__swatch',
      }}
    />
  )
}
```

The built-in markup uses predictable global BEM hooks with the `rc-*` namespace, so external CSS can target classes like `.rc-sketch`, `.rc-sketch__body`, `.rc-sketch__swatch`, or theme modifiers such as `.rc-sketch--dark`.

### Override CSS custom properties

Use CSS variables when you need to retheme the built-in look without replacing component structure:

```css
.profile-color-picker__root {
  --rc-color-surface: #101418;
  --rc-color-surface-elevated: #161b22;
  --rc-color-border: #2f3843;
  --rc-color-text: #f3f6fb;
  --rc-color-shadow: 0 16px 40px rgb(0 0 0 / 0.35);
}
```

### Legacy styles migration

`styles` still works as a deprecated compatibility layer for runtime inline overrides on supported slots. Prefer it only while migrating older integrations.

```
import React from 'react'
import { SketchPicker } from 'react-color'

const sketchPickerStyles = {
  default: {
    picker: {
      boxShadow: 'none',
    },
  },
}

export default function Component() {
  return (
    <SketchPicker styles={sketchPickerStyles} />
  )
}
```

Migration guidelines:

- Move persistent visual customizations from `styles` into CSS classes or CSS variables.
- Use `classNames` when you need stable hooks for slots such as `root`, `body`, `controls`, `field`, `swatch`, `pointer`, or `triangle`.
- Keep the aggregate stylesheet as an optional shortcut only; granular CSS imports remain the preferred path when you only render one or two pickers.
