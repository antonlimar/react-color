# Контекст для агентов и контрибьюторов

## Назначение репозитория

Форк **react-color** с целью модернизации: TypeScript, актуальный toolchain (сборка, тесты, Storybook, доки), снятие legacy (Babel 6, Webpack 1 в доках и т.д.). Сохраняем совместимость публичного API там, где это возможно без major-релиза.

## Постоянные инструкции для агентов

Этот файл — единый источник постоянных инструкций для ИИ-агентов в репозитории. Все постоянные правила должны считаться встроенной частью `AGENTS.md`.

## Карта каталогов

| Путь          | Назначение                                                              |
| ------------- | ----------------------------------------------------------------------- |
| `src/`        | Исходники библиотеки (компоненты, хелперы, точка входа `index.ts`).     |
| `examples/`   | Отдельные мини-приложения-примеры; не публикуются как часть npm-пакета. |
| `docs/`       | Сайт документации (сборка через скрипты из `package.json`).             |
| `.storybook/` | Конфигурация Storybook для визуальной разработки историй.               |

Сгенерированные артефакты **`lib/`** (CJS) и **`es/`** (ESM) не править вручную — только через скрипты сборки.

## Команды

| Команда                   | Назначение                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------- |
| `npm run build`           | Полная сборка пакета: `lib/` (CJS) + `es/` (ESM).                                             |
| `npm run lib`             | `tsc`-сборка `src/` → `lib/` (CommonJS, пофайлово).                                           |
| `npm run es`              | `tsc`-сборка `src/` → `es/` (ESM, пофайлово) + перепись импортов на `lodash-es`.              |
| `npm test`                | `vitest run` + ESLint.                                                                        |
| `npm run test:unit`       | Только unit/UI-тесты через Vitest + jsdom + Testing Library.                                  |
| `npm run test:watch`      | Vitest в watch-режиме.                                                                        |
| `npm run eslint`          | Линт `src/`, `docs/`, `scripts/`, `test/` и repo tooling через ESLint flat config.            |
| `npm run storybook`       | Dev Storybook 10 на порту `6006` (framework `@storybook/react-vite`).                         |
| `npm run build-storybook` | Статическая сборка Storybook в `.out/`.                                                       |
| `npm run docs-server`     | Локальный dev-сервер документации на Vite (`http://localhost:9100/`).                         |
| `npm run typecheck`       | `tsc --noEmit` проход по `src/`, `docs/`, `scripts/`, `test` через `tsconfig.typecheck.json`. |
| `npm run docs-dist`       | Production-сборка документации через Vite в `docs/build/`.                                    |

## Артефакты сборки

| Путь          | Назначение                                                                                |
| ------------- | ----------------------------------------------------------------------------------------- |
| `lib/`        | Пофайловая CommonJS-сборка библиотеки; публикуется в npm и поддерживает deep imports.     |
| `es/`         | Пофайловая ESM-сборка библиотеки; публикуется в npm и поддерживает deep imports.          |
| `index.d.ts`  | Корневая точка входа для типов пакета (`types` в `package.json`).                         |

## Публичный API (имена экспортов — договор с потребителями npm)

Точка входа: [`src/index.ts`](src/index.ts) — одновременно **default** (Chrome через `ColorWrap`) и именованные экспорты.

**Default export:** компонент Chrome (обёрнутый через `ColorWrap`), как в оригинальном пакете.

**Именованные экспорты (пикеры):**  
`AlphaPicker`, `BlockPicker`, `CirclePicker`, `ChromePicker`, `CompactPicker`, `GithubPicker`, `HuePicker`, `MaterialPicker`, `PhotoshopPicker`, `SketchPicker`, `SliderPicker`, `SwatchesPicker`, `TwitterPicker`, `GooglePicker`.

**Именованные экспорты (сборка своего пикера / общие куски):**  
`CustomPicker`, `Alpha`, `Checkboard`, `EditableInput`, `Hue`, `Raised`, `Saturation`, `Swatch`.

**Правило:** не переименовывать и не удалять эти экспорты без **major** версии и записи в **CHANGELOG**. Новые экспорты — по semver (minor/patch по смыслу).

## Решения фазы 1 (зафиксировано)

- **Минимальная версия React (цель модернизации):** **16.8+** — достаточно для хуков в примерах и для типичных зависимостей экосистемы; переход на **18** как минимум — отдельное решение при обновлении peer и тестов (см. фазу 4 в [`PLAN.md`](PLAN.md)). До явного поднятия `peerDependencies` в `package.json` библиотека остаётся на классовых компонентах.
- **Имя npm-пакета:** в этом форке в `package.json` пока сохраняется **`react-color`**. Переход на scoped-имя (`@org/...`) или другое имя — только при осознанном решении, с **major** и записью в **CHANGELOG**.

## Ограничения и соглашения

- **Совместимость и breaking changes:** по возможности сохранять стабильный публичный API и избегать лишних breaking changes. Изменения entry (`main` / `module`), структуры `lib/` / `es/`, deep imports и `exports` делать только осознанно и с отражением в документации.
- **Документация библиотек:** для актуальных API, примеров кода и документации по сторонним библиотекам и инструментам предпочтительно использовать **Context7 MCP**, а не полагаться только на память модели.
- **Peer:** `react` (и при использовании DOM — `react-dom` в приложении пользователя). Не раздувать peer-диапазон без обсуждения минимальной версии React в README/AGENTS.
- **Стили:** сейчас **reactcss** и inline-стили. Массовую смену подхода (например, на CSS Modules) не делать одним PR — отдельное решение после стабилизации TS и тестов.
- **Минимальный дифф:** менять только то, что нужно для задачи; не рефакторить «заодно» несвязанные модули.

## TypeScript-миграция

Миграция идёт по плану в [`PLAN.md`](PLAN.md): сначала toolchain, затем файлы блоками.

- **Строгость:** включать `strict` и отдельные строгие флаги поэтапно; избегать одного гигантского PR с тысячами ошибок.
- **Публичный API:** поддерживать и дополнять типы публичных пропсов компонентов, экспортируемых из [`src/index.ts`](src/index.ts). После стабилизации публикации не забывать про `types` и при необходимости `exports` в `package.json`.
- **Согласованность:** до завершения миграции сохранять существующие имена и паттерны соседнего JS/TS-кода; не дублировать логику только ради типов.

## Тесты и миграция тестов

- **Текущее состояние:** исторически проект использовал Jest и `spec.js`; при работе учитывайте, что репозиторий находится в переходном состоянии.
- **Цель миграции:** использовать **Vitest** или актуальный Jest вместе с **@testing-library/react** вместо **Enzyme**.
- **Новые и переписанные тесты:** по возможности писать в формате `*.spec.ts` / `*.spec.tsx` и опираться на паттерны Testing Library: рендер, роли, пользовательские события.
- **Принцип миграции:** сохранять поведенческие проверки при рефакторинге; не делать синтаксическую перепись тестов «заодно» в том же PR, что и крупная функциональная правка.
